# Intent: Fix PR review comment assisted-by attribution format

## Problem

When drafting PR review comments, the assisted-by attribution line format was wrong, without triggering smith-gh-pr and smith-style skills.

### Evidence

1. **Wrong format #1 - "on behalf of" pattern**: "Posted by Claude Code on behalf of @username"
   - Source: basic-memory notes
   - Violation: smith-gh-pr/SKILL.md:74 explicitly forbids: "No 'on behalf of' line"

2. **Wrong format #2 - missing model id entirely**: `Assisted-by: Claude` (without `:model-id`)
   - Used plain "Claude" without the required model identifier
   - Violation: smith-style requires format `Assisted-by: «AGENT_NAME»:«MODEL_VERSION»`
   - The colon and model ID are mandatory, not optional

3. **Wrong format #3 - hand-typed instead of scripted**
   - Both wrong formats were hand-typed, not pulled from `attribution.sh`
   - smith-style/SKILL.md: "do not hand-type the trailer" — "hand-typing is where the format drifts"

4. **Correct format** (smith-style/SKILL.md):
   - `Assisted-by: Claude:claude-sonnet-4-5` (or whatever the actual running model is)
   - Generated by `smith-ctx-claude/scripts/attribution.sh`
   - The model ID must be the ACTUAL session model, not a made-up string

5. **Skills not triggered**: smith-gh-pr and smith-style should have been loaded when drafting PR review comments but weren't

## Root Causes (Investigation Complete)

### Primary Issue: Protection Mechanisms Failed — **CONFIRMED: Advisory Ignored**

**Investigation Result**: The protection mechanisms worked, but I ignored the advisory.

1. **skill-router hook (UserPromptSubmit)**: ✅ **WORKED CORRECTLY**
   - Pattern matched PR review keywords correctly
   - Surfaced `smith-gh-pr`, `smith-style` as candidates
   - Advisory: "Invoke the relevant one via the Skill tool"

2. **Skill Tool Invocation**: ❌ **FAILED — ADVISORY IGNORED**
   - skill-router surfaced required skills
   - Agent proceeded without invoking them
   - Result: Protection rules never loaded

3. **smith-gh-pr + smith-style skills**: ❌ **NEVER LOADED**
   - Skills contain the correct attribution rules
   - Never loaded because Skill tool not invoked
   - Their rules would have prevented the errors

### Secondary Issues (Symptoms)

1. **Stale/incorrect memory**: Basic-memory notes recorded wrong formats
2. **Hand-typed attribution**: Bypassed `attribution.sh` script
3. **Format errors**: "on behalf of" + missing `:model-id`

## Core Gap Identified

**The skill-router is ADVISORY, not ENFORCE.**

It says "Invoke the relevant one" but there's no mechanism to ensure I actually do it. I can (and did) ignore the advisory and proceed without loading the skills.
